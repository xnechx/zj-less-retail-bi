01. RETAIL KPI DICTIONARY & FORMULATION LOGIC SLIDE 02 / 05
Normalized Retail Performance Methodology

คู่มือตัวชี้วัดค้าปลีกและสูตรคำนวณ

ในธุรกิจรีเทล เราไม่สามารถเปรียบเทียบยอดขายรวมระหว่างสาขาใหญ่ที่เปิดทุกวันกับสาขาเล็กที่เปิดไม่เต็มเดือนได้โดยตรง รายงานนี้จึงใช้ตัวชี้วัดมาตรฐาน "Per Store Day (PSD)" โดยมีหัวใจสำคัญคือ ตัวหาร (Denominator) จะต้องใช้ "ผลรวมจำนวนวันที่ร้านเปิดขายจริงรวมกันทุกร้าน" (Total Store Operating Days) ไม่ใช่การเอาสาขามาคูณวันตรงๆ เพื่อความแม่นยำสูงสุดตามจริง:

BPSD Baht / Store / Day
ยอดขายเฉลี่ยต่อร้านต่อวัน (บาท) Total Sales (Baht) / Total Store Operating Days
UPSD Units / Store / Day
จำนวนชิ้นที่ขายได้ต่อร้านต่อวัน Total Units Sold / Total Store Operating Days
TCPSD Ticket Count / Day
จำนวนใบเสร็จ (บิล) ต่อร้านต่อวัน Total Transactions / Total Store Operating Days
GPPSD Gross Profit / Day
กำไรขั้นต้นเฉลี่ยต่อร้านต่อวัน (บาท) Total Gross Profit (Baht) / Total Store Operating Days
TA Ticket Average
ยอดซื้อเฉลี่ยต่อ 1 ใบเสร็จ (Basket Size) Total Sales / Total Transactions (or BPSD / TCPSD)
UT Units / Transaction
จำนวนชิ้นสินค้าเฉลี่ยต่อ 1 ใบเสร็จ Total Units Sold / Total Transactions (or UPSD / TCPSD)
%GP (Gross Profit Margin) - อัตรากำไรขั้นต้น Profit Margin %
สัดส่วนกำไรขั้นต้นเมื่อเทียบกับยอดขายรวมทั้งหมด (Total Gross Profit / Total Sales Revenue) × 100
⚠️ ข้อควรระวังและข้อจำกัดการใช้งาน (BI Constraint Tip) ตัวชี้วัดที่เกี่ยวกับจำนวนบิล ได้แก่ TCPSD, TA, UT จะสามารถใช้ตัวกรอง (Filter) ได้เฉพาะข้อมูลฝั่ง Store Detail (เช่น รายสาขา, โซน, หรือโปรไฟล์สาขา) เท่านั้น เนื่องจากในการวิเคราะห์ทางธุรกิจจริง การดูพฤติกรรมจำนวนบิลรายสาขานั้นเพียงพอแล้ว หากต้องการให้จำนวนบิลมีความยืดหยุ่นจนสามารถกรองรายสินค้าได้ เราจำเป็นต้องนำตารางดิบระดับ POS Receipt ที่มี ticket_id (หลายล้านแถว) มาสแกนและทำการคำนวณแบบคำนวณสด (COUNT DISTINCT) บน Looker Studio ซึ่งกินข้อมูลมาก ระบบจะโหลดช้าลงมหาศาล และไม่คุ้มค่าทางเศรษฐศาสตร์ (Cost-Performance Trade-off)
02. DASHBOARD CORE CAPABILITIES SLIDE 03 / 05

4 ฟีเจอร์หลักในการวิเคราะห์

ออกแบบฟังก์ชันการใช้งานหน้า Dashboard ให้ตอบโจทย์ทั้งผู้บริหารและทีมปฏิบัติการหน้าร้าน

Executive Matrix Analysis
วิเคราะห์ยอดขายแบบไขว้มิติ (Matrix) ระหว่าง โซนพื้นที่ (East, South, BKK, Isan) กับ รูปแบบสาขา (สถานที่ท่องเที่ยว, ออฟฟิศ, ที่พักอาศัย) เพื่อเปรียบเทียบศักยภาพและหาแนวทางเพิ่มยอดขายในแต่ละกลุ่มสาขา
Hierarchy Drill-Down
เจาะลึกโครงสร้างสินค้าเป็นลำดับชั้น (Hierarchy Drill-Down) ตั้งแต่ภาพรวมระดับกลุ่มสินค้าหลัก (Group Item), หมวดหมู่ย่อย (Category) ไปจนถึงระดับรายการสินค้าแต่ละตัว เพื่อวิเคราะห์พฤติกรรมการซื้อได้อย่างตรงจุด
YoY Growth Tracking
เปรียบเทียบผลงานและแนวโน้มการเติบโตเทียบกับช่วงเดียวกันของปีที่ผ่านมา (YoY Growth Engine) เพื่อค้นหาทิศทางของตลาดและกลุ่มสาขาที่มีศักยภาพสูงในการเติบโต ช่วยสนับสนุนแผนการลงทุนขยายธุรกิจในอนาคต
Missing Item Alert 🔥
ระบบวิเคราะห์ช่องว่างโอกาสในการเพิ่มยอดขาย (Assortment Opportunity Gap) โดยตรวจสอบสินค้าขายดีของแต่ละหมวดหมู่ที่หน้าร้านยังไม่มีจำหน่าย เพื่อประมาณการโอกาสในการสร้างรายได้เพิ่มขึ้นทันทีที่นำเข้าสินค้ามาเติม

💡 Operational Design Rationale

ทำไมส่วน Missing ถึงไม่จำเป็นต้องเลือกเวลาย้อนหลัง?
เพราะในการใช้งานจริง ระบบถูกออกแบบให้รัน Pipeline อัตโนมัติใน "ทุกๆ สิ้นเดือน (Monthly Batch Job)" เพื่อให้ผู้จัดการสาขามุ่งเน้น Action สั่งของเข้ามาเติมทันทีแบบ "เดือนต่อเดือน" จึงไม่จำเป็นต้องใช้ Time-range Filter เพื่อลดความซ้ำซ้อนและสร้าง Focus ในการปฏิบัติงานจริง

1

Item-Level BPSD Ranking

คำนวณยอดขายเฉลี่ยต่อร้านต่อวัน (BPSD) ของแต่ละสินค้าจากทุกสาขา เพื่อจัดอันดับหา Top 10 สินค้าขายดีที่สุดในแต่ละ Category

2

Zero-Touch Condition

ตรวจสอบไขว้กับข้อมูลร้าน โดยสินค้า 'Missing' ต้องเข้าเงื่อนไข: ไม่มีทั้งยอดขาย + ไม่มีทั้งยอดสั่งซื้อ + ไม่มีสินค้าในสต็อก เพื่อความแม่นยำ

3

Revenue Impact Projection

แสดงค่า BPSD ของสินค้าตัวนั้นในรายงาน เพื่อให้ผู้จัดการร้านรู้ทันทีว่า หากนำเข้าสินค้าตัวนี้ จะช่วยสร้างรายได้เพิ่มให้ร้านเฉลี่ยวันละกี่บาท

💡 Looker Studio Integration: Advanced Data Blending

เพื่อป้องกัน "ตัวหารคลาดเคลื่อน" เมื่อกรองสินค้า (เช่น หากกรองเฉพาะ "สินค้าชาเขียวพรีเมี่ยม" ซึ่งบางสาขาขายไม่ได้ หากดึงจากตารางยอดขายรายสินค้าอย่างเดียว ตัวหารจะหดเหลือเฉพาะวันที่ของสาขาที่ขายได้ ส่งผลให้ค่าเฉลี่ย BPSD สูงเกินจริง) เราจึงใช้ Data Blending บน Looker Studio เพื่อเชื่อมตารางยอดขายรายสินค้า เข้ากับตารางยอดขายร้านรายวัน (ถ้าร้านมียอดขายเท่ากับว่าเปิดร้าน) ช่วยให้การคำนวณค่า BPSD ยืดหยุ่นและถูกต้อง 100% เสมอ

⚡ BigQuery Optimization: Table Partitioning

การสร้างตารางบน BigQuery เพื่อต่อเข้า Looker Studio หากมีฟิลด์ที่เป็นวันที่ (Date) **ควรทำการ Partitioning ทุกตาราง** เพื่อความประหยัดและรวดเร็ว เนื่องจากหากไม่มีการ Partition ทุกครั้งที่ Looker Studio มีการรีเฟรชหรือประมวลผล ระบบจะทำการสแกนข้อมูลทั้งตาราง (Full Table Scan) ทุกครั้ง แม้เราจะกดกรองเฉพาะช่วงวันที่หน้ารายงานแล้วก็ตาม
